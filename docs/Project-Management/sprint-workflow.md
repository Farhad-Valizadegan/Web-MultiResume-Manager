# Sprint Workflow

Status: Recommended workflow
Reviewed: 2026-10-06 (Europe/Berlin)
Source baseline: 0ca188f. This is documentation evidence, not production certification.

Agree a short goal and select ready backlog items. Record scope, acceptance, dependencies and available verification. The iteration may revisit requirements/design while implementing, rather than following folders as a waterfall sequence.

Track progress through reviewable outcomes and findings. At closure compare actual increment with the goal, attach sanitized code/test/manual evidence, move unfinished work back to the backlog, and record next decisions. A completed sprint may produce no release; a release may combine several increments.

The [sprint template](../Sprints/sprint-template.md) starts prospective records. No historic sprint date, effort or team ceremony is invented from commit timestamps. Existing version history remains in Releases.
