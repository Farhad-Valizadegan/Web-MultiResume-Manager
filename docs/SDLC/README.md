# SDLC Documentation

Reviewed: 2026-10-06. Source baseline: 0ca188f.

These eight areas organize engineering responsibilities. Work can revisit requirements, analysis and design inside an iteration; folder numbering does not impose a waterfall execution sequence. Project Definition supplies product boundaries, Project Management owns backlog/status, Sprints record actual increments and Releases identify delivered source.

- [Planning](01-planning/README.md)
- [Requirements](02-requirements/README.md)
- [Analysis](03-analysis/README.md)
- [Design](04-design/README.md)
- [Implementation](05-implementation/README.md)
- [Testing](06-testing/README.md)
- [Deployment](07-deployment/README.md)
- [Maintenance](08-maintenance/README.md)

Security, privacy, accessibility, reliability, maintainability and documentation apply across the areas. Requirements identify acceptance, analysis identifies rules/risks, design describes the technical response, implementation produces the change, and verification records evidence at the appropriate boundary. Production deployment/recovery needs actual environment evidence.
